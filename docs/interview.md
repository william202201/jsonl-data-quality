**数据质检脚本｜个人项目｜Python / JSONL / SQLite**

- 开发 JSONL 数据质检命令行工具，支持字段缺失、类型、长度、标签及跨文件重复检测，输出带文件名与行号的 CSV 问题清单和汇总。
- 采用有界逐行读取和临时 SQLite 重复索引，隔离坏行并继续扫描；通过测试覆盖 Unicode 长度边界、损坏 JSON、跨文件重复及退出码。
- 提供可配置规则、模拟数据、离线报告及 GitHub Actions，便于复现和接入批处理流程。

## 三分钟演示

1. 打开 `examples/sample.jsonl`，找到缺失字段、过短文本及重复主键。
2. 运行 `python -m jsonl_quality --input examples/sample.jsonl`。
3. 打开 HTML 和 CSV，按文件/物理行定位问题；展示 `first_file` / `first_line` 追溯重复。
4. 修改规则中的长度阈值重跑，解释为什么中文字符数不等于字节数或 token 数。
5. 加 `--fail-on-issues`，展示非零退出码如何让数据流水线暂停。

## 常见追问

- 为什么用 JSONL？可按物理行扫描，单行损坏不影响后续记录；换行必须在 JSON 字符串中转义。
- 去重键怎么选？`id` 用来发现主键冲突；输入+输出用来找内容重复，两者含义不同。
- 内存有界吗？不读取完整文件；单行有上限，重复索引在磁盘。SQLite 缓存和单行解析仍会使用内存。
- 第一条重复也会标记吗？当前是流式检测，只标记后出现的行并引用首条。若要整组回溯，需增加第二遍扫描。
- 质检通过是否能直接用于训练？只代表通过当前结构规则，还需要抽样、语义与业务质量评审。
- 规范化会误报吗？会。NFKC 与空白/大小写折叠是明确的业务选择，可关闭；不声称语义重复识别。
